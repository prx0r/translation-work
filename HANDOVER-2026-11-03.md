## How to do L4 well (tips earned this session)

These are entanglement lessons, not style preferences. Each one cost
someone a bad verse.

### 1. Sanskrit first, layers second — no exceptions
Re-parse the verse's `sanskrit_cite` yourself before reading anything
else: cases, compounds, verb tense, word order, where the sentence
lands. T1/L0/argmap/L2/C1/L3 are *ideas about the verse*; the Sanskrit
*is* the verse. On spanda v1 this took 30 seconds
(saḥ jayati śivaḥ ekaḥ spandavān svapratiṣṭhaḥ | yaḥ antarvaktram
rasayati) and it set the whole verse: verb-first victory cry,
relative clause as arrival. If any layer disagrees with your parse,
the Sanskrit wins — record the correction in craft_notes.

### 2. Read the whole stack before touching a layer
T1 quick gloss → L0 tokens/morph/forks → argmap premises/inference →
L2 voice → C1 essence indices + rasa block → L3 frozen lines.
Never rewrite living voice unasked (mistakes.md rule 15). For spanda
v1 I changed exactly two diction items vs L3 ("self-standing" for
"self-established", "tasting/inward" for "savors/inner") — same
l0_ids, same meaning, new music. If you find yourself rewriting
sentences, stop: you are writing L2 again, not L4.

### 3. Name the sthāyin first, in one phrase
Everything downstream hangs off this. Here: *vismaya resolving into
śama* (wonder at unmeasured greatness settling into the unmoved
ocean), straight from the C1 rasa block. The sthāyin picks the
final word ("face" — the arrival point, dark vowel, at rest), the
vowel arc (bright conquers/Śiva → dark face/alone), and what counts
as a valid refrain. No sthāyin, no song — go back to C1.

### 4. Small edits + one device per verse
An L4 verse should be L3 with: re-lining for breath, at most one
musical device (refrain, anaphora, chiasmus, enjambment, dash
caesura), and end-weight moved to the doctrine word. Consult
`lore/bank/songcraft-bank.json` for the *device*, never the style.
Spanda v1's only device is the closing refrain ("conquers alone"
ringing the opening "conquers"). Resist a second device; two
devices is arrangement, not setting.

### 5. Trace discipline is the law (validator-enforced)
- Every L4 `l0_ids` entry must already exist in the corresponding L3
  (`validate_song.py` enforces subset, not just existence — stricter
  than the schema). Easiest compliance: copy L3's list whole, as the
  paramarthasara DRAFTs do. A rhyme word that needs a new slant
  fails: re-ground it in L3 first, or drop the rhyme.
- `essence_maps` must be valid indices into C1 essence (here: [0],
  single essence).
- No `/` anywhere in L4 lines. Exact diacritics (Śiva, Māyā, Śambhu)
  — the schema rejects ASCII stand-ins outright.
- L4 MAY share sentences with L3 (it is a setting, not a new layer).
  The L2/L3 no-share rule does not apply here. Still verify L4
  against L2: sharing with L2 means you copied the wrong layer.

### 6. Justify every edit in craft_notes, or it didn't happen
The DRAFT-file form is `craft_notes + form + l4{} + reads_against`.
For each edit write: what changed, the Abhinavagupta frame it
serves, and the read-aloud audit (stress it out loud; if a line
won't scan it won't parse). Write justification *as you compose* —
reconstructed justification is decoration. Name which
transmission-table rows fired
(`lore/rasa/english-transmission-2026-11-03.md` §2).

### 7. One verse at a time. No batches. No exceptions.
DRAFT files live outside `data/` (`<work>/L4-<song>-vNN.DRAFT.json`).
Merge into `data/<song>.l4.json` ONLY on owner verdict. The first
verse of a work sets the voice and gets extra scrutiny — spanda v1
was approved on first presentation *because* it was minimal. If
you batch 5 verses, you will flatten the voice into wallpaper
(rule 15/17; this mistake already happened once with kramastotra
L3 and was reverted in full).

### 8. Validate before presenting, confess what fails
Run `schemas/l4.py` validation + the subset check yourself before
showing the owner anything. If beauty requires breaking a rule
(the owner explicitly permits this), flag the exact break with
the beauty-reason — never silently. Beauty may break rules; it
may not hide the breakage.

### 9. Rasa is in the diction, never in a label
Never name the rasa in a song line ("in wonder..."). Carry it in
word choice and rhythm, and justify each choice against the
sthāyibhāva with a specific reason tied to it — "throbbing keeps
the Sanskrit's spanda-physicality; a static word like 'vibrant'
would aestheticize it" is a reason; "sounds better" is not.

### 10. The gate is a proxy (applies to L4 too)
`check.py` CANONICAL with 0 failures means the machine found no
defects. It cannot hear music. Read every L4 aloud against the
rule (mistakes.md #8/#9): when proxy and rule disagree, the rule
wins and the gate is wrong.

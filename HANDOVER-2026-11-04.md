## 3. The meticulous L4 method (as actually practiced, v01–v120)

Per verse, in this order — no skipping, no batching of judgment
(batches are commits, never thoughts):
1. **Sanskrit first, parsed by hand** (cases, compounds, verb position and
   tense, where the sentence lands). Layers are ideas about the verse;
   the Sanskrit IS the verse. Disagreement → Sanskrit wins, correction noted.
2. **Read every prior layer for that verse**: T1 gloss → L0 tokens/morph/forks
   → argmap premises/inference/uncertainties → L2 voice → C1 essence indices
   + rasa block → L3 frozen lines → Vṛtti/M00089 where collated.
3. **Name the sthāyin in one phrase** + the verse's color inside the song's rasa.
   Name which transmission-table rows fire
   (`lore/rasa/english-transmission-2026-11-03.md` §2: end-weight, enjambed
   unpacking, deixis control, vowel arc, rupture-point, close-shape…).
   Consult `lore/bank/songcraft-bank.json` for the device (Ryder = the
   rhyme-twist warning), never the style.
4. **Draft from L3 with small edits**: rhythm, order, sound, punctuation —
   at most one musical device per verse (dash-caesura, colon landing,
   end-weight shift, enjambment flip). Copy L3's l0_ids/essence_maps whole
   (subset = equality is safest). No `/` anywhere. Exact diacritics
   (Śiva, Māyā, Śambhu) — readability never costs exactness.
5. **Write craft_notes AS YOU COMPOSE** (reconstruction after the fact is
   decoration): every edit + Abhinavagupta frame + read-aloud audit +
   **every rejected wording with the exact killer** (which layer, which
   transmission row, which read-aloud fact killed it — per
   `process/L4-SONG-PROCESS-2026-11-03.md` §5: a choice with no named rival
   is a preference, not a decision). Plus reads_against (exact T1/L2/L3/C1/
   argmap strings used).
6. **Validate before presenting**: `schemas/l4.py` + subset-vs-L3 check +
   L4-vs-L2 no-share check (write one; the gate checks L2/L3 only, but the
   rule is no floating English anywhere) + read aloud (if it won't scan it
   won't parse). Beauty may break rules; it may NEVER hide the breakage —
   flag the exact break with the beauty-reason.
7. **DRAFT file outside `data/`** (`<work>/L4-<song>-vNN.DRAFT.json`);
   merge into `data/<song>.l4.json` only on owner approval (first-verse
   verdict sets the voice; standing approval may cover the rest — ask).
8. **Per-song**: `validate_song.py --song X --work W` (0 errors) →
   `proof_record.py` (gate PASS) → commit (working DRAFTs + data + proofs).

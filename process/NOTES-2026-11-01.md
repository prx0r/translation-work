# NOTES — hand-craft approach (2026-11-01)

*Written after the user corrected the batch-script approach. These notes record what
changed and why, so the next work follows the new standard.*

## What was wrong before

- I used `/tmp/transform_work.py` to scaffold T1/L0/argmap/L2/C1 for 10 works in one
  session. The output passed every mechanical gate (schemas, proof, meta regex, shared
  sentences) but was shallow: generic rasa ("bhakti (devotion)" for every passage),
  argmap inference copy-pasted from C1 EXPLANATION, placeholder FUNCTION/LOCAL
  CONTEXT/BOUNDARY/RELATED, L0 with morph_unknown=true and only t1-draft source,
  no scholarly alternatives, no peer review, no honest uncertainties beyond a
  generic line.
- I treated "0 meta hits" and "0 shared sentences" as proof of quality. They are not.
  They are proxies. The ghatakarpara lesson (rule 9) already said this; I forgot it.
- I marked 10 works "gold" in REGISTRY.json without human review and without the
  scholarly depth of the original 2 golds (ghatakarpara, spandasandoha). That inflated
  the gold count and polluted the concept database with 400+ skeleton concept files.
- I reverted all of that after the user called it out. Registry back to 2 gold.

## What is different now

### 1. One work at a time, fully by hand

No scaffolding script. Each layer is written with Read/Write/Edit, reading the
source, the existing T1.md, L2.md, C1.md, and one focused web search for
scholarship. The user explicitly said "NO SCRIPTS ... HAND CRAFT EACH ONE BY ONE".
I follow that.

### 2. Source must be complete before anything else

The legacy `passages.jsonl` for several works (bhairavastava, paramarthacarca,
anubhavanivedana) carried only the second half of each verse. I now verify the
full verse against T1.md and GRETIL before writing T1/L0/argmap/L2/C1, and update
`passages.jsonl` + `source_sha` + `sanskrit_cite` to the full verse. A truncated
source invalidates every downstream layer (rule 4).

### 3. L0 is a scholarly audit, not a gloss dump

- `morph` is stated for every token (case/number/gender or tense/mood/voice+root),
  `morph_unknown` set to false. Previously it was true for every token.
- `grounds` state the grammatical basis, not "T1 quick gloss carried".
- `source` remains t1-draft where no fork exists; genuine forks get grammar /
  lakshmanjoo / dyczkowski / ksemaraja-vivrti / witness-* with grounds.
- `fork` is none|live|resolved; live/resolved only with >=2 options and analyzed
  morph. I do not invent forks, but I do analyze morphology.

### 4. Argmap is a terse logical reconstruction, not a copy of C1

- `premises` are distinct logical statements (not `essence[0]`).
- `inference` is a condensed argument (not a copy of EXPLANATION).
- `uncertainties` are honest gaps specific to that verse (obscure forms, open
  antecedents, undecoded chronograms), not a generic line.
- `speaker`, `question` are verse-specific.
- `traces.l0_ids` lists every token id; `sanskrit_sha` matches the (full) source.
- No certainty/uncertainty labels beyond stating what is unresolved.

### 5. C1 states the matters, carries rasa, names what the verse DOES

- `essence` is a list of atomic propositions (like ghatakarpara's 4), not one
  sentence.
- `rasa{}` block is filled per passage with dominant, sthāyibhava, justification
  tied to the verse's sthāyibhāva and vyabhicāri. No generic "bhakti (devotion)".
- `EXPLANATION` carries rasadhvani: Sanskrit-in-parens anchors, no quotes, no
  document-reference ("the verse", "the poem", "the hymn", "the close", "reader").
- `BOUNDARY` records honest gaps.
- `FUNCTION`, `LOCAL CONTEXT`, `RELATED` are verse-specific, not placeholders.
- Broad meta scan (not just narrow regex) is run by hand: read the C1 against
  the rule, not the gate.

### 6. L2 carries rasa in word choice and rhythm

- Plain English that traces to L0, cite byte-exact.
- No metacommentary sentences ("The stotra opens with...") — those belong in C1
  or lore, not L2.
- `supplied[]` logs bracketed insertions (when any).

### 7. Concept pass is post-translation and enriched

- `build_concepts.py` reports missing; I create skeletons with `lookup_concept.py`
  or by hand, then enrich with sources, rasa, works, related terms.
- Reformat KEY TERMS to em-dash multi-line so coverage is meaningful (not
  vacuous 0/0).
- Concept DB grows from the work; it is a derivative, not a prerequisite.

### 8. Proof records are honest

- `proof-*.json` written per passage with source_sha, l0 counts, c1_words,
  c1_metacommentary [], needs [human-review], gate PASS. They are machine-proposed,
  not human-signed. `signoff.json` is never fabricated.

### 9. STATUS and registry

- STATUS.json notes state "MANUAL REVIEW PERFORMED" and that script gates are
  proxies.
- Registry updated only after the work is genuinely hand-crafted and reviewed.
- targets.md queue consulted; one work at a time.

### 10. Web search is used for scholarship

- One focused search per work (editions, translations, scholarship, rasa context).
- Findings woven into C1 EXPLANATION and argmap as support, not claims.
- Peer review file updated with scholarly takes.

### The canonical process (what the repo demands)
The stack: SOURCE (sha-pinned) → T1 (fast translation, pada-split) → L0 (scholarly audit, morph + ranked options) → ARGMAP (terse logical, fork adjudication) → L2 (plain English, rasa-carried, cite byte-exact) → C1 (essence + 7 sections + rasa block) → C2 (prompt renders) → Proof (B1-B8) → Site.

Invariants: L0.chosen == T1.quick_gloss unless revised; fork live|resolved ⟺ ≥2 options; argmap traces resolve; L2 lists ≥1 l0_id; C1 essence non-empty; standard render with all 7 sections; C2 prompt non-empty + maps_to; verse/song coverage exact.

### The 9 binding rules (mistakes.md) + rule 10 (no scripts/bulk)
1. No quoted English gloss-words in C1 — EVER.
2. No metacommentary in C1 — EVER (narrow grep is floor, not ceiling; run broad scan).
3. L2 vs C1 must be different layers — zero shared sentences.
4. T1 must cover the FULL source — parse rate alone proves nothing.
5. No copy-paste lore across passages.
6. Mark uncertainty, never invent.
7. One work at a time, manually.
8. C1 states the MATTERS, never the document.
9. The gate is a proxy — never trust a PASS that contradicts the rule.
10. No scripts, no bulk — hand-craft every work, one at a time. Scripts are proxies, never authors.

### What "evocative rasa" means
Rasa in L2 means choosing English that evokes the same emotional response as the Sanskrit. Not synonym swaps. Not punctuation. Words and configurations that make the reader FEEL what the Sanskrit makes the sahṛdaya feel. Each change must be justified by the verse's rasa (sthāyibhāva). "This word sounds better" is not a reason. "This word evokes the rasa the Sanskrit evokes, because [specific reason tied to the sthāyibhāva]" is a reason.

C1 carries rasa in the rasa{} block: dominant (the rasa named), sthāyibhava (the stable emotion), justification (why this rasa, tied to vibhāva/vyabhicāri). The C1 EXPLANATION names what the verse DOES (relish/camatkāra), not just what it says.
